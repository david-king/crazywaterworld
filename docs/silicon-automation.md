# 硅矿自动化：功能与协议依据

协议依据为本机微信缓存第 76 版 `_src_chunks_.wxapkg` 的 protobuf 和同版 `_subpackages_main_.wxapkg` 客户端逻辑，以及当前 `config_cn` 配置。私有缓存不纳入仓库。在线验证覆盖单队初等空位派遣、已产矿后撤回、自然返港、汽油消耗与重连防重；名单抢占及发现目标后实际攻击尚未完成在线验证，具体边界见下方实测记录。

## 总览中的硅矿概览

在「总览 → 世界概览」下方可直接查看硅矿，无需开启硅矿自动化：

- 本周期已领／最大次数、剩余奖励、今日共享抢占次数，以及北京时间的奖励重置时间。周期次数是三天累计，不作为今日收益展示。
- 己方舰队的矿区、矿位、战力、耐久、本次占矿采集次数，以及下次产奖、行军抵达或维修结束倒计时。首奖之前提示「首奖后可撤回」并禁用撤回按钮。
- 初等矿有三个个人矿位，中、高等矿按服务器返回的公共容量展示。点击、轻触矿位，或用键盘聚焦后按回车，在矿卡底部查看占领者、战力、联盟和采集次数。切换矿位、选队和确认共用预留空间，刷新沿用当前选择。
- 各品质的可能产出来自 `ChipMineCfg.reward`；产出数量不作为保证收益。

「自动刷新」开关与秒数输入仅控制硅矿视图，默认开启、30秒，可设5–300秒；浏览器记住选择，不改账号的挂机配置。选队区显示「暂无可用舰队」时也按此间隔更新。可随时点「刷新舰队」重新核对目标和队伍，自动刷新关闭时仍可手动刷新。总览隐藏、已有可确认的舰队或正在发送请求时暂缓自动刷新。切换账号、暂停或断开连接会清除旧结果；读取失败保留上次结果并明确提示；超过三倍刷新间隔（至少90秒）未同步的倒计时显示待同步，到时不会直接假定奖励到账。该接口仅使用 `ChipMineList`、`ChipMineReward`、`MyFleets` 、串行的 `ChipMine` 和 `AllGuildAbstraction` 读取，不修改配置、预算或游戏状态。

`npm run test:silicon-overview` 覆盖只读协议、个人／公共矿位、共享额度、部分失败、跨周期和HTTP账号隔离。`npm run test:silicon-overview:browser` 使用虚构数据检查交互、迟到响应、倒计时、主题和320px／390px手机布局，截图保存在 `output/silicon-overview/`。

### 快捷操作

- 在空位底部选择「派遣采集」，查看舰队战力和耐久后选队确认。如果空位已易主，需要重新选择。
- 派遣或抢占发出后，矿位显示「已派遣」「抢占中」或「待确认」。重载页面时从当前账号的派遣记录和舰队状态恢复，已安排的矿位不能重复派遣。刷新选队不会出征。
- 在其他玩家占领的公共矿位选择「抢占矿位」，选队并确认。发送前重新核对目标昵称、联盟、战力、每日共享次数、该舰队的抢占上限和安全名单。舰队出发后，抢占结果以游戏结算为准。
- 在己方舰队卡片或自己的矿位选择「撤回舰队」，在对应矿卡底部确认。首次采集完成后可免费撤回。
- 这些操作可在硅矿自动化关闭时使用，不改变总开关、队伍开关、目标策略或占领时段；本次手动选择不受自动占领时段和矿级选择限制。派遣仍检查实际汽油库存、待确认消费、奖励上限、耐久与编队条件，以及共享舰队／待确认任务锁。
- 每次确认绑定账号、连接、配置和矿位，2分钟有效；同一确认重复提交共用结果，不再次发送。费用和目标均从服务端确认记录取得，不接受客户端修改。结果不明时保留持久化预算和舰队锁；只有已确认完成、明确拒绝或明确未发送才释放对应记录。

概览定时刷新仍只读。点击快捷操作准备确认时会核对已完成任务并同步账本证据，不发送游戏写入；只有点击「确认派遣／确认抢占／确认撤回」才提交。操作完成后自动刷新概览，取消、切号或迟到响应不会触发操作。`npm run test:silicon-overview` 同时运行快捷操作与HTTP回归；`npm run test:silicon-shortcuts:browser` 使用隔离账号验证完整页面链路，截图保存在 `output/silicon-shortcuts/`。

### 自动采矿与联盟名称

概览已移除自动化快捷配置。总开关、每队参与、矿级和抢占规则仍在原「硅矿配置」中调整，已保存配置保持不变。手动撤回不关闭自动采矿；希望某队撤回后不再自动出发时，应先到配置页关闭该队自动参与，再手动撤回。刷新开关不影响自动采矿执行。

联盟名称与世界概览共用同一解析规则：优先使用同次只读同步的联盟摘要，按64位联盟ID精确换算编号后匹配自定义名称；名称为空、摘要缺项、读取失败或编号冲突时，使用当前场景 `CityCfg` 中该联盟出生主城的默认名，并在名称提示中说明来源。两者都不可用才显示「联盟 #编号（名称未同步）」；编号为0时显示「无联盟」。默认名称不套用其他场景，也不改变同盟判断或派遣规则。

## 已有与新增

此前仅有通用舰队状态识别（`chipWar.rewardTs` 防止其他玩法抢用采矿舰队），没有矿区读取、采矿派遣、抢占、撤回或硅矿自动化配置。本次新增 `src/silicon-mining.mjs`，接入游戏配置的硅矿分组和挂机调度；新总开关、三个舰队开关、维修与加速均默认关闭，保存配置不会启动挂机。

| 截图功能 | 实现与边界 |
| --- | --- |
| 硅矿总开关、三个独立舰队 | 每队可勾选多个矿级，任一所选等级有合规矿位即可出发，清空等级则暂停该队新派遣。每队独立配置空位模式、战力排序和上限、安全名单、失败次数、追击、普通维修和行军加速。停用不会清除子项选择。 |
| 角色 16 级解锁 | 真实规则还要求 `GameplayOpenCfg` 的“芯片”赛季开放。当前表为 `[0,0,1,1]`，即 S1、S2 不开放，S3 起按当前赛季开放日检查，不能只按图片的 16 级派遣。 |
| 单日领奖上限 | 0 为不额外限制，始终服从服务端 `myRewardTimes/maxRewardTimes/rewardResetTime`。服务器奖励自动发放，没有伪造“领奖”接口。持久保存周期计数增量，达到用户日上限后停止新派遣并申请撤回。 |
| 达限撤回 | 客户端明确要求 `DispChipMinePlayer.rewardTimes > 0` 才能撤回。首轮采集未满 15 分钟时仅停止新派遣，等服务器允许后撤回，不能承诺立即中断首轮奖励。 |
| 占领时段 | 北京时间 `HH:mm-HH:mm`，支持多个时段和跨午夜，空列表全天。时段外同样先停派、再按服务器规则撤回已启用队伍。 |
| 空位和抢占 | 普通模式先空位。只空位时不攻击也不追击；初等矿永不攻击已有玩家。中、高矿只攻击配置战力比例内、非同盟、非安全名单的玩家；战力可升序／降序。 |
| 每舰每日抢占上限 | 持久独立计数，发送前占用。另读取服务器玩家共享 `fightTimes/maxFightTimes`，不能把三队各 30 次误当成服务器允许总 90 次。上限耗尽仍可普通空位采集。 |
| 单敌失败限制 | 已匹配角色 ID 时按舰队和 ID 记录当日失败，改名后继续计数。仅有昵称时沿用舰队、昵称和联盟编号。已确认派出后归队、未曾占领目标位置记一次失败；未知请求不算失败也不重发。次日重新计数。 |
| 安全名单 | 按昵称勾选玩家后自动保存角色 ID，也可补充完整昵称。安全 ID 按同服角色的当前昵称和联盟编号核对，资料读取失败的舰队暂缓抢占。手动抢占也遵守保护。补充昵称忽略大小写，联盟使用 `guildIdx` 数字编号。 |
| 追击 | 三日奖励周期开始后的配置分钟数内，只追击真实游戏黑名单里且本工具已通过个人胜利战报核实击败过的目标。目标必须仍满足矿级、战力、安全名单、失败、用户日上限和服务器次数限制。无匹配时待命，不回退空位／普通敌人。周期窗口结束恢复普通采矿。 |
| 指定玩家追杀 | 每队可按昵称从世界舰队、世界聊天和游戏黑名单中选择对手，也可填写补充昵称，默认关闭。改名后按 ID 读取新资料。补充昵称独立生效，忽略大小写，同一目标换用 ID 后应移除旧昵称。名单内合规目标优先于空位，无目标可采空位，不能攻击名单外玩家；开启后优先于旧追击窗口。安全玩家/联盟、同盟、初等矿不抢占、只占空位、战力、耐久、失败/次数及实际汽油库存检查均继续生效。矿位无 UID。按 ID 查到的同服资料须与矿位的完整昵称和联盟编号相符。多个已查角色或多个可见矿位对应同一组昵称与联盟时，跳过该 ID 的追杀。 |
| 追杀撤退策略 | `never` 持续采集；`afterReward` 每次占矿首次奖励后撤回，下一轮重新寻找名单目标或空位；`onTarget` 仅发现可攻击的名单目标且满足后续预算时撤回，回港后重新读目标再派遣。两种撤回都服从服务器 `rewardTimes > 0` 首奖限制，不会强行中断首轮15分钟。 |
| 普通维修 | 自动维修只针对选定空闲舰队，读取 `FleetRepairParam` 实时报价，用 `RepairFleetRequest` 修复；按实际汽油库存扣除待确认消费后检查，不设置额外汽油保留量或费用上限。 |
| 逐队去程与回城加速 | 每队的去程和回城各设开关、剩余时间目标和每日钻石预算。默认关闭，预算 0 钻石。去程核对已确认派往矿区的航程。回城核对从本次派遣或撤回的矿格返回所属城池的航程。回城可在领奖达限或时段结束后执行。所有消费均受全局钻石预算和保留量约束。 |
| 调度与推送 | 普通间隔 10 分钟；启用追杀或有效追击配置时 2 分钟。矿区、奖励额度、舰队、战力、战报和库存推送唤醒串行检查，配置更改由统一调度提前检查；不在推送回调直接派遣。 |

## 协议实证

以下字段按真实 encode/decode 和客户端调用共同核实。`tools/describe.mjs` 的老正则只认某一 protobuf 命名空间别名，可能漏报第 76 版的消息和数组字段，因此本次同时检查了实际编码函数并在测试中往返编码。

- `ChipMineListRequest {}` → `ChipMineListResponse {chipMines: DispChipMine[]}`：`gridId/color/occupiedNum/positionNum`。
- `ChipMineRequest {gridId}` → `ChipMineResponse {occupiedNum,positionNum,occupiedPositions,rewardInfo,fightTimes,maxFightTimes}`。响应不带 gridId，逐矿串行查询避免错配。
- `DispChipMinePosition {index,player}`；`DispChipMinePlayer {nickname,avatar,power,rewardTimes,guildIdx,title?,fleetId?,skinId?}`。客户端 `ChipMinePop` 将带 `fleetId` 的位置认作己方队伍。
- `OtherPlayerInfoRequest {playerId}` 按字符串角色 ID 读取当前昵称、区服和联盟编号。角色资料与矿位均在本轮读取，发送前重新核对。
- `ChipMineRewardRequest {}` → `ChipMineRewardResponse {rewardInfo}`。`LoginProxy` 将其作为世界信息初次读取的一部分；没有领道具或扣费参数。
- `ChipMineRewardInfo {myRewardTimes,rewardResetTime,maxRewardTimes}`；`SCChipMineRewardInfo` 只推送 `maxRewardTimes`，不能根据它推断已领次数增加。
- `ChipMineSendFleetRequest {gridId,index,fleetId}`。`SelectTroopPop` 限制一次选一队，汽油使用 `WorldParamCfg` 的“采集硅矿消耗汽油”（当前 500）。
- `ChipMineRetreatRequest {fleetId}`。`ChipMinePop` 发送前检查该己方位置 `rewardTimes > 0`。通用明确拒绝包括 `CHIP_WAR_RETREAT_LATER` 和 `CHIP_WAR_NO_REWARD_TIMES`。
- `ChipMineCfg` 品质 `BLUE=3`、`PURPLE=4`、`ORANGE=5` 分别对应初等、中等、高等矿。槽位数量以响应为准，不硬编码旧赛季的 7／16 个位置。
- `MyFleetsResponse.fleets[]` 返回精确舰队状态、战力、耐久、行军时间与 `chipWar.rewardTs`；`FleetState.QUEUING=5` 且带 `chipWar` 表示采矿。
- `BlackListRequest {}` → `BlackListResponse.list[]` 含 `playerId/nickname/avatar`。矿位没有 UID，当前追击以游戏黑名单中唯一的完整昵称，加已验证胜利目标的联盟编号进行匹配；不会添加或删除游戏黑名单。
- `CampaignReportsRequest {pageNo:0}` 读取个人战报。`type=11 (CHIP_WAR)`、`mySide=0`、`win=true`、`chipWar.fleetId/color`、发送后时间匹配后，再用 `CampaignReportDetailRequest {campaignId}` 中 `battles[].rightCamp.player.nickname` 核对对手，才记录已击败。不能通过仅“战力大于对方”推断必胜。
- `RepairFleetRequest {buildingId}` 使用 `FleetRepairParamResponse.unitRepairCost/unitRepairTime`。
- `SpeedUpFleetRequest {buildingId}` 使用 `WorldParamCfg`“行军加速消耗”（当前 30 钻）；每次只能按真实新 `moveEndTs` 确认。

`TipsCfg`“硅矿争夺”写明：每队每 15 分钟一奖、玩家每三天共享最多 100 奖、首轮 15 分钟后可撤退、每天玩家共享最多 30 次抢占。实际奖励额度可能因权益变化，因此执行以响应为准，不把 100／30 写死为服务端上限。

## 持久化、预算和未知结果

- 设置沿用账号设置文件及自动保存。`automation-usage.json` 中 `silicon-state:<world>` 保存日奖励基线、失败和已击败记录；账号账本隔离，世界编号参与键，跨区不会复用队伍状态。
- 没有当日历史基线时，服务端只有三日累计次数，无法准确反推出今天单独领取多少。首次使用保守把当前周期计数计入今日，之后以增量记录；这可能少派，但不会凭空把今日清成 0。
- `silicon:<world>:<fleet>` 在发送前持久占用汽油与舰队。派遣要看到实际向该矿行军或己方队伍占领该位置才确认。未知请求即使下一次读到空闲也不重发，跨日和重启不会清除 pending。
- 派遣、维修及钻石加速使用独立持久键。明确拒绝或确定未发才取消；超时、结果不明继续占预算。普通修复结束不能误认为未知加速成功。
- 发现名单目标后撤回会在 `silicon-retreat:<world>:<fleet>` 保存目标意向。返航期间保留下一次攻击的虚拟汽油、共享次数和目标占位，其他硅矿舰队不会重复为同一目标或不足的实际汽油库存撤回；意向不是实际消费，不写成攻击次数。确认回港后释放意向并重新检查，没有目标时不会沿用旧目标盲发。其他玩法锁和高优先级预留仍会阻止为追杀放弃矿位。
- 汽油 pending 与联盟情报、世界 Boss、海盗、城战、货轮共用，舰队实际占用与其他玩法互斥。硅矿默认处于派遣优先级最后。

## 离线验证

`node tools/selftest-silicon.mjs` 使用 `tools/fixtures/silicon.mjs` 的虚构角色与真实 protobuf 编解码。覆盖默认关闭、赛季门控、只读预览、三舰队、名单/战力、空位与低矿、服务器共享与本地独立上限、失败换目标、黑名单和胜利战报、日奖励与撤回、跨日未知防重、共享预算、维修／加速、配置中途关闭与推送调度。任何测试都不建立真实游戏连接。
